# Internationalization (English / Urdu)

Spec requirement: multi-language UI (English/Urdu) with RTL support for Urdu (spec section 4, story A1).

## Setup
`src/i18n/index.ts` bootstraps `i18next` + `react-i18next` with resources from `src/i18n/locales/en.json` and `ur.json`. Initial language is detected from the device locale (`expo-localization`), falling back to English.

## Adding/changing strings
- Never hardcode user-facing text in a component — always `const { t } = useTranslation()` then `t("namespace.key")`.
- Every key added to `en.json` must have a corresponding key in `ur.json` in the same change. A PR/commit that adds an English-only string is incomplete.
- Keep the namespace structure flat and feature-scoped (`nav`, `home`, `customers`, `customerForm`, `khata`, `entry`, `reports`, `settings`, `lock`) — match whichever screen/feature owns the string. Add a new top-level namespace only for a genuinely new feature area.

## RTL
- `setAppLanguage(language)` (in `src/i18n/index.ts`) changes the active language and, if the RTL-ness changed, calls `I18nManager.allowRTL` / `forceRTL`.
- **`I18nManager.forceRTL` does not flip a running app's layout live** — RN only fully applies it after the JS bundle reloads. Any UI that lets a user switch language (first-run setup wizard, Settings) must trigger a reload after calling `setAppLanguage` (e.g. via `expo-updates`' `Updates.reloadAsync()` once that dependency is added in Phase 6) or explicitly tell the user to restart the app.
- Write layout code so it mirrors correctly under RTL: prefer `marginStart`/`marginEnd`/`paddingStart`/`paddingEnd` over `marginLeft`/`marginRight`, and rely on `flexDirection: "row"` (which RN mirrors automatically) rather than hardcoding element order for left/right placement.
- Any hand-drawn directional icon (arrows, chevrons) needs an explicit mirror check under Urdu — React Navigation's built-in header/back-button already handles this, custom icons don't.

## Testing a translation change
There's no automated i18n test yet. Manually verify by calling `setAppLanguage("ur")` (once wired into Settings in Phase 6) and confirming: the string renders correctly, the layout doesn't visually break under RTL, and no key falls back to showing the raw `namespace.key` string (which means it's missing from one of the two locale files).
